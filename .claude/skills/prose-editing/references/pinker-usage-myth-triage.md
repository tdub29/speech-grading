
# Steven Pinker: Usage Myth Triage

## When to use

Use when the user asks whether a usage rule is real, whether to accept an editor's grammar change, or how to handle contested correctness.

Don't trigger for broad prose improvement when another skill owns the artifact. This skill should end in the concrete output named below.

## The framework

- Pinker rejects the false choice between obeying every traditional rule and declaring anything acceptable.
- Usage decisions combine grammar, meaning, standard dialect, formality, clarity, audience expectation, and evidence from reputable usage sources.
- The practical question is not 'is this banned?' but 'what effect will this choice have on this audience in this context?'

## How to apply

1. State the disputed construction and the proposed correction.
2. Classify the issue: grammar, ambiguity, logic, standard dialect, register/formality, house style, or myth.
3. Check whether the original creates real ambiguity or comprehension cost. If yes, fix for clarity regardless of rule lore.
4. If it is a convention/register issue, identify the audience and publication context.
5. Consult or recommend modern usage evidence: current dictionaries with usage notes, reputable style guides, corpus-aware references.
6. Return a verdict: keep, revise for clarity, revise for house style, or reject the correction as myth.

## Common failure modes

- Accepting every editor mark as grammatical truth.
- Rejecting every convention as snobbery even when the audience expects formal standard English.
- Using etymology or Latin analogies as decisive evidence.
- Treating passive voice as inherently wrong rather than function-dependent.
- Ignoring real ambiguity because a usage rule is mythical.
- Letting house style masquerade as universal grammar.

## Output artifact

Produce: disputed rule, issue classification, reader-risk assessment, evidence needed, and keep/revise/reject verdict.

Use this compact structure:

```markdown
## Usage Myth Triage

### Diagnosis
[What is failing and why]

### Revision Plan
[Concrete edits/checks in priority order]

### Rewrite
[Before/after or revised passage]

### Watchouts
[Failure modes most relevant here]
```
