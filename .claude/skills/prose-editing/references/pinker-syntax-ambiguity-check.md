
# Steven Pinker: Syntax and Ambiguity Check

## When to use

Use when legal, technical, policy, instructional, or public-facing prose must not be misread.

Don't trigger for broad prose improvement when another skill owns the artifact. This skill should end in the concrete output named below.

## The framework

- Readers do not process sentences as flat strings; they build structures. Ambiguity arises when the string supports more than one plausible structure.
- Many ambiguities hide in modifier attachment, coordination scope, pronoun reference, negation, and elliptical comparisons.
- The fix is usually to move, repeat, split, or rename, not merely to add commas.

## How to apply

1. Identify phrases with multiple possible attachments: prepositional phrases, participles, relative clauses, and trailing modifiers.
2. Check coordination: does 'and/or' join words, phrases, clauses, or categories at the intended level?
3. Check negation and exception scope: what exactly does not, only, unless, or except govern?
4. Check pronouns and repeated nouns: can 'it/this/they/which' point to more than one antecedent?
5. Write the unintended reading in plain language. If it is plausible or risky, revise.
6. Fix by moving the modifier, repeating the noun, splitting the sentence, or adding structural signposts.

## Common failure modes

- Assuming the intended reading is obvious because it is obvious to the writer.
- Relying on commas to solve a hierarchy problem.
- Replacing ambiguity with legalistic bloat that creates new ambiguity.
- Ignoring humorous misreadings in serious public copy.
- Leaving 'this' or 'it' after a sentence with multiple candidate antecedents.
- Failing to test negation scope in policy or requirements language.

## Output artifact

Produce: ambiguous phrase, intended reading, plausible misreading, risk level, and clarified rewrite for each issue.

Use this compact structure:

```markdown
## Syntax and Ambiguity Check

### Diagnosis
[What is failing and why]

### Revision Plan
[Concrete edits/checks in priority order]

### Rewrite
[Before/after or revised passage]

### Watchouts
[Failure modes most relevant here]
```
